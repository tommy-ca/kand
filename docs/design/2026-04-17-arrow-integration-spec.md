# Technical Specification: Arrow Zero-Copy Integration (Updated V6.3 Macro Engine)

## Overview
This document specifies the technical architecture for the `kand` technical analysis engine, focusing on universal automation and enterprise-grade durability.

## 1. Unified 5-Tier Architecture
Every indicator in the library aims to provide five distinct implementation tiers:
1.  **`_raw`**: Zero-validation, high-performance computational core (slices).
2.  **Safe Wrapper**: Validated API with NaN handling (slices).
3.  **`_arrow`**: Zero-copy batch processing using Arrow arrays and `BlockPool`.
4.  **`Stateful` (Indicator trait)**: Encapsulated single-stream stateful object.
5.  **`Batch` (BatchIndicator trait)**: Vectorized multi-stream parallel processor.

## 2. Universal Macro Engine (`kand_indicator!`)
To scale the 5-tier architecture to 100% of the library, the `kand_indicator!` macro automates generation from a single logical definition.

### 2.1 Logic Modes
- **`recursive`**: Logic that depends on previous scalar state (e.g., EMA, RSI). Automates feedback loop and simple scalar persistence.
- **`sliding_window`**: Logic that requires a historical buffer of $N$ values. Automates circular buffer management, rolling sums, and V5.2 compliant persistence.

### 2.2 Advanced Macros (V6.5 Planned)
- **`kand_indicator_multi!`**: Planned to handle indicators with multi-output requirements (e.g., MACD, BBANDS) and complex multi-input sliding windows (e.g., CCI, MFI, DX) with parallel circular buffers.

### 2.3 Durability Standards (V5.2)
- **Columnar Persistence**: All internal state (counters, cursors, buffers) is serialized as `__kand_` prefixed columns in the state `RecordBatch`.
- **Atomic Commits**: Transactional updates ensured via state cloning in multi-component indicators.

## 3. Memory & Performance
- **Zero-Allocation Hot-Path**: All `Batch` indicators utilize the thread-local `BlockPool` for instantaneous memory reuse.
- **SIMD-Ready Alignment**: All buffers generated by the macro engine enforce 64-byte alignment.
- **Overhead Target**: Local computational overhead for Arrow/Stateful variants should remain below **15%** of the raw core.

## 4. Development Workflow
- **TDD Requirement**: Every macro-generated indicator must include parity tests verifying bit-identical results between functional and stateful variants.
- **Automated Quality**: Code must pass `prek` (Rust fmt/clippy, Python ruff/ty) before merging.
